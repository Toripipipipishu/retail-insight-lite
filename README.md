# Retail Insight Lite

**売上・在庫・仕入れ分析 — 小売業の現場経験をもとに制作した、ブラウザで動く業務改善ツール。**

在庫CSVと販売履歴CSVから、商品ごとの売れ方と在庫の偏りを可視化し、「何日以内に、何個発注するか」の判断を支援します。HTML・CSS・JavaScriptで構成し、サーバーやAPIキーなしで試せます。

## まず試す

1. このリポジトリの **Code → Download ZIP** からダウンロードし、すべて展開します。
2. 展開したフォルダ内の **index.html** をEdgeまたはChromeで開きます。
3. **「サンプルで試す」**を選びます。架空の雑貨店12商品・90日間の分析を表示します。
4. 「発注提案」「商品別の販売推移」「仕入れ予算・発注計画」を切り替えてお試しください。
5. 「新商品動向」では **「架空の商品情報で試す」**で追加のサンプルを読み込めます。

アプリの起動にNode.jsやインストール作業は不要です。index.htmlだけを取り出さず、同梱ファイルを一緒に保管してください。

## 解決したい課題

小売の現場では、売上だけでは仕入れを判断できません。在庫の残り方、販売速度、納品までの日数、仕入れ予算を併せて見る必要があります。この作品では、そうした判断に使う情報をCSVからまとめて確認できるようにしました。

| 現場の問い | 実装した機能 |
| --- | --- |
| 売上に貢献する商品はどれか | 商品別売上・数量・粗利、ABC分析、手動の運用ABC |
| いつ、どれだけ補充するか | 7/30/90日販売速度、在庫日数、発注点・推奨数量・発注期限 |
| 予算内で何を優先するか | 指定予算・翌月予測・売上目標の3方式による発注案 |
| 曜日や月内の日にちで売れ方が変わるか | 曜日別・日にち別・特定日付の商品ランキング |
| 新発売後に販売速度が変わったか | 商品別の日次推移、7/30日移動平均、任意の日末在庫履歴 |
| 入荷した新商品がまだ売れていないか | 登録日・初回入荷日を使った未販売判定と参考スコア |

## 制作で取り組んだこと

- **業務要件の整理：** 小売・在庫管理・仕入れ・業務改善の経験から、発注判断に必要な項目と計算条件を設計。
- **入力データの扱い：** CSVの列名差異、文字コード、返品、取消、欠損原価、店舗別の商品照合を考慮。
- **判断根拠の表示：** 発注点、安全在庫、予算配分、新商品スコアを説明可能なルールとして実装。
- **検証：** 計算部分と画面部分を分離し、CSV処理・日付境界・補充・予算・新商品判定をテスト。

ChatGPT・Codexを活用して制作した個人のポートフォリオ作品です。実店舗への導入実績や売上改善の実績を示すものではありません。

## 技術構成

HTML / CSS / Vanilla JavaScript。グラフはSVGで描画し、外部ライブラリやAPIに依存しません。

- `core.js`：CSV読込・正規化・売上在庫集計・補充計算
- `time-analysis.js` / `product-trend.js`：曜日・日付・商品別推移
- `budget-analysis.js` / `new-products.js`：予算配分・新商品分析
- `app.js` / `*-ui.js` / `merch-ui.js`：画面表示と操作
- `samples/`：架空CSV、`tests/`：計算テスト

## データと制約

- 同梱データはすべて架空です。業務CSVの外部送信処理はありません。読み込んだデータはメモリ内で処理し、再読込・終了で消えます。
- スマレジの一般的な列名を参考にした非公式ツールです。提携・認定製品ではなく、実際の各CSV出力形式との照合は未完了です。
- 在庫は基準日時点のスナップショットです。売上の減少だけで欠品と需要低下の原因を断定しません。
- 発注案は参考値です。発注残、ケース入数、送料などは未対応で、利益最大化や予測精度を保証しません。
- 年間の季節補正は完全な12か月の履歴がある場合のみ使います。1年分では成長・セールと季節性を十分に分離できません。
- スマホ向け表示とPWA構成を用意していますが、最新画面・実機インストール・オフライン動作の確認は未完了です。
